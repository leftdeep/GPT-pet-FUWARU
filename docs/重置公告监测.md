# 重置公告监测

2026-10-10（0.52 布局）：顶部固定卡片分为三层，第一层并排显示重置计时与“立即检查”，第二层显示检查状态及主页入口，底部等宽三列显示最近成功检查、下次检查和上次公告时间。窄窗口和较长状态信息支持正常排版，历史单独滚动；检查中按钮显示“正在检查…”，监测暂停时显示“已暂停”。时间值悬停可查看包含年份的完整时间。构建及界面回归检查通过，示例预览位于 `verification/0.52/native-smoke/reset-summary-preview.png`。

2026-10-08（0.52）：赠送重置卡或额外额度已加入持久提醒。升级后在新鲜数据源中重新检查到最近 48 小时内的重置卡公告，会补提醒一次；原先仅用于历史记录的去重标识不会误吞此次通知。

主数据源为 [codex-reset.com](https://codex-reset.com/developers) 的 `/api/timeline` 和 `/api/feed`，主站不可用时查询 [codexreset.today](https://codexreset.today/api/) 的公开 JSON。数据来自这些网站收录的 Tibo 推文，不直接抓取 X 页面。没有 AI 调用，不会消耗聊天 Token，也不向数据源发送账号、用量或聊天记录。

正常启动立即检查，之后按上次请求起点每小时检查一次。休眠恢复后检查是否到期；隐藏到托盘仍继续运行，完全退出则停止。断网等失败依次在 5、15、60 分钟后重试，HTTP 429 遵守 Retry-After。手动检查也遵守最短一分钟的请求间隔。实际提醒延迟包含轮询间隔及上游网站更新延迟。

首次成功检查建立历史基线，不弹出旧公告。后续新发现、最近 48 小时内的明确预告、完成公告或赠送重置卡 / 额外额度公告会生成持久提醒；模糊暗示、否认赠送、缺少原帖的人工记录和过期数据只进入历史。原帖 ID 与公告阶段共同去重，切换数据源、重复刷新或重启不会重复生成已读提醒。未点击关闭的提醒会跨重启恢复。

预告和赠送额度不会改变上次重置时间。完成公告会更新“距上次公开重置公告”，并请求现有用量服务刷新。公告时间未必等于实际执行时间，本账号余额始终由现有账号用量接口读取；只有日期的记录不虚构小时与分钟。

右键“重置历史…”打开桌宠中心的对应标签页，页面提供“立即检查”按钮，其下方的“打开 Tibo 主页”按钮使用默认浏览器打开 https://x.com/thsottiaux，监测暂停或检查中也可使用；设置标签页提供监测开关。历史页面显示最近成功检查时间、下次检查时间、上次完成公告、最多 30 条公告以及原帖入口。只有历史页面可见时才每分钟更新相对时间。

监测复用 .NET 的 HTTP 与 JSON 功能，无独立进程、浏览器、数据库或新增运行时依赖。缓存为 `local-data/reset-watch.json`，上限 100 KB，去重标识最多 512 个，未读队列最多 5 条，单个 HTTP 响应上限 512 KB。公共原文只用于当次分类，不保存推文全文或图片。多个本项目桌宠实例通过 `reset-watch.lock` 共享一个监测实例，其他实例读取共享历史，避免重复请求和通知。

新增命令行入口：`--reset-history` 打开历史，`--check-reset` 手动检查。诊断用 `--status` 的 `runtime-status.json` 包含监测状态与气泡显示状态。验证记录位于 `docs/verification-current/0.37`，其中界面截图使用测试公告。
