# 动作素材固定流程

把原视频放进 `animation`，在 `animation/actions.json` 登记一次，双击根目录 `导入桌宠动作.cmd`。新素材依次完成基础转换、按待机校色、横向轮廓与头部/双脚锚点校准、验证和安装，正常退出再启动当前桌宠，保留位置、大小、开关和成长存档。这个流程只更新素材，使用 `pet-release.json` 指定的当前发布程序。

单纯复制视频不会自动猜测它的动作。未登记的 MOV、WebM、MP4 会出现在 `output/animation-import/last-run.json` 的 `pendingSources`；本次停止，不切换桌宠。暂不使用的视频可在 `ignoredSources` 写明原因。当前 `普通待机.mov` 已登记为旧素材，默认待机继续采用审核过的 `待机2.mov`。

## 常用操作

```powershell
# 转换和验证，生成独立素材包；暂不切换正在使用的桌宠
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/import-pet-actions.ps1

# 转换、验证成功后安装（双击入口的默认行为）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/import-pet-actions.ps1 -Apply

# 重新解码检查所有缓存，仍然不重新编码未变视频
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/import-pet-actions.ps1 -VerifyAll
```

省略 `-Apply` 不切换素材选择或重启程序；如果正在使用的恰好就是配置中的输出包，重建它的清单后，播放器会在下次打开菜单时刷新。需要完全隔离的新素材预览时，将 `outputSkin` 改为另一个 `assets/imported` 子目录。

需要 Python 3.11+ 和项目内 `runtime/ffmpeg.exe`。脚本优先使用 Codex 自带 Python，其次使用 PATH 中的 Python；也可用 `-Python "C:\路径\python.exe"`。新素材的自动校准与完整对比需要 NumPy/Pillow，Codex 自带 Python 已包含它们；基础转换、审核素材和缓存复用仍使用标准库。脚本不联网、不调用 AI、不自动安装依赖。

Windows 安装须使用桌面用户会话；`-Apply` 在 Codex 受限账号中会先停止，不启动隔离桌宠或改写设置。普通生成和预览仍可在受限环境执行。Codex 已获安装授权时使用桌面会话执行，并用程序的只读 `--status` 确認实际加载的素材，不能只凭新进程 ID 判断已安装。

## 登记新动作

在 `actions` 数组末尾添加一个条目，例如：

```json
{
  "key": "Wave",
  "source": "animation/挥手.mov",
  "label": "挥手",
  "group": "ClickInteraction",
  "loop": false,
  "conversion": { "referenceStart": 0 }
}
```

`key` 是唯一动作键，`label` 是菜单文字，`loop` 决定是否循环。`group` 可选 `Idle`（待机）、`ClickInteraction`（点击互动）、`Walking`（移动）。当前程序单击会随机选择「点击互动」中的动作，默认待机仍是 `Idle`；移动规则沿用当前程序。将互动动作设为 `loop: false`，即可完整播放一次后返回待机。点击互动的菜单顺序为开心跳跃、害羞、生气、屈膝礼。生气保留完整 240 帧 / 10 秒；`margin: 0.04` 用于容纳转身时完整衣摆与尾巴，只改变预留空边，不缩小人物。

`referenceStart` 为秒数：选这个时刻开始的五帧测量人物站立高度、水平中心和脚底。必须是没有爱心、光点、道具干扰、头部和双脚清楚且与待机相近的站姿。新素材的完整校准要求明确填写；局部模板测量不具备通用姿态识别能力。通用基础转换器省略时仍使用首尾参考，首尾高度差超过 15% 会拒绝。开心跳跃明确使用开头，避免结尾爱心把人物身高算大。

`defaults` 固定全库参数：640×640、24 fps、CRF 40、站立高度 348.333 像素、脚底线 576 像素。站立比例仍为 209/384。整段保持一次固定缩放和平移，避免动作播放过程中忽大忽小；全片可见轮廓用于安全检查。`conversion` 可以覆盖 `referenceStart`、`contentRegion`、`crop`、`frameRange`，以及 `fps`、`width`、`height`、`crf`、`lossless`、`margin`、`bboxAlpha`、`targetHeight`、`feetY`。目标身高比例必须与基础包一致。

2026-10-10 的既有动作升级采用顶层 `qualityProfiles: "animation/quality-profiles.json"`。文件保存旧动作的原 MOV 指纹、原成品路径与指纹、裁切/缩放/补边、固定颜色与锚点及原配方。重制只允许等比例改变画布、站立高度、脚底线和最终质量；颜色、参考时刻、分段、布局、人工锚点及源内容改变时拒绝自动覆盖。`reviewedFinal` 保留，校正从 MOV 只应用一次。须保留这些档案引用的旧成品，不能按“当前 skin.json 未引用”直接清理。

可选的 `conversion.colorCorrection` 保存固定 RGB 曲线和鲜艳色保护参数，`conversion.anchorCorrection` 保存头部与双脚的固定校准。两个已确认互动动作使用 `reviewedFinal: true`：审核指纹包含完整颜色/锚点配方与原 MOV/成品 SHA-256，直接复用已确认成品，禁止重复校正。

需要制作新的候选结果时，独立配置可使用 `colorFromReviewed: true` 从审核 WebM 校色，或 `anchorFromReviewed: true` 从审核颜色视频校准；两者不同时启用，也不与 `reviewedFinal` 同时启用。已确认成品的源或校准参数改变后直接停止，先在另一个输出目录复核并更新审核记录，不能悄悄退回原 MOV 或继续累加变形。细节见 [动作锚点校准](动作锚点校准.md)。旧 `widthFromReviewed` / `widthCorrection` 试验接口已移除。

有角落标记时，可明确添加 `"contentRegion": [280,0,720,720]`；仅适用于确实采用该构图的源视频。检测区域不是自动抠图工具，必须保证完整角色、尾巴和特效位于区域内。不要直接把旧视频的检测区域套给新视频。

如果完整动作无法在共同身高下容纳，脚本报错并保持原包，不能为了通过检查单独缩小人物或裁掉特效。需要重新检查参考帧/检测区域，或在新基础包中统一调整全部动作的标定。

## 新素材默认校色与锚点校准

正式配置顶层的 `"calibration": "animation/import-calibration.json"` 开启整个新素材流程，普通新增条目无需另写颜色曲线或校准程序。策略引用 `animation/anchor-calibration.json` 中已审核的 Idle 视频哈希、头部区域与双脚接触点；参考视频变化时先停止，避免沿用过期标注。匹配审核指纹的既有七段成品直接复用，尤其开心/害羞不再次校色或拉伸。

1. 原 MOV 完整转换成无损 VP9 Alpha 中间视频，统一身高和脚底基准，单独缓存。首次处理需要编码；调整颜色或锚点时复用这个视频。
2. 从声明的站姿窗口与待机窗口中选取不透明、较亮且低色度的像素，拟合固定 RGB 单调曲线。各采样点偏移最多 14，保护鲜艳眼睛、腮红与红色特效；曲线整段固定，校色前后解码 Alpha 必须完全一致。已有显式 `colorCorrection` 时使用该曲线。
3. 头部区域测量中心与横向轮廓，双脚通过已审核鞋底局部模板在附近小范围匹配。横向比例限制在 0.94–1.08，微小自动差异不拉伸；结合双脚中点和头部中心做一次固定仿射调整。纵向比例始终为 1，脚底只允许固定小偏移，保留跳跃、下蹲等真实纵向变化。头部高度差超过 2 像素、参考姿势晃动或鞋底匹配含糊时拒绝自动校准。
4. 校色与锚点阶段无损编码，几何处理使用预乘 Alpha；全片检查完整角色与特效边界，校准 Alpha 与计划变换一致。分段最后裁取，起步/循环/收步共用完整视频的同一站姿、色调与锚点配方。
5. `preview.html` 为新素材提供「待机 / 基础转换 / 校准后」完整动作视频和站姿测量图，`动作键.calibration.json` 保存实际曲线、锚点、横向比例、匹配质量与颜色误差。拟合参考时刻未必是动作首尾，仍需检查完整衔接；脚本不修改动作编排或循环接缝。

局部模板只适用于同一角色的相近站姿，不能保证任意新 MOV 都能自动识别。返回 `needs_calibration`（退出码 3）时，已安装清单保持原样。先查看报告中的测量 PNG，选择更合适的 `referenceStart`；仍有遮挡或鞋形差异时可在新增动作中写人工标注，例如：

```json
"calibration": {
  "normalizedVideoSha256": "从该动作.calibration.json复制的64位哈希",
  "feetContacts": [[186,344], [202,344]],
  "headCenter": [188.45,175.19],
  "scaleX": 1.04
}
```

坐标必须来自报告指定的**测量图**，不能填原 MOV 坐标或抄另一个动作。640 标准输出仍在 384×384 的已审核参考坐标中测量头部与鞋底，再将固定仿射变换按 640/384 应用于完整高清帧；报告区分 `measurementCanvas` 和 `outputCanvas`。`feetContacts` 是左右鞋底接触点，`headCenter` 是同一头部参考区域的中心，`scaleX` 为显式横向比例；可只覆盖不能可靠测量的字段。原视频或标准化配方变化会使哈希失效，要求重新标注。不要删除全局策略来绕过失败，也不要把尾巴或特效的外接框当成双脚。人工调整继续接受位置、姿态、完整边界与 Alpha 检查。

通用 `转换透明MOV.cmd` / `import-alpha-video.py` 保留为基础转换工具，本节完整流程只通过 `导入桌宠动作.cmd` / `import-pet-actions.ps1` 执行。

## 分段走路

同一个源视频可以登记多个动作，共用同样的参考帧和转换参数，只改变 `frameRange`：

```json
{
  "key": "WalkStart",
  "source": "animation/走路3.mov",
  "label": "转身提裙",
  "group": "Walking",
  "loop": false,
  "conversion": {
    "referenceStart": 2.4583333333333335,
    "contentRegion": [280,0,720,720],
    "frameRange": [0,59]
  }
}
```

范围从 0 开始、右端不包含，按输出帧率计数。现有走路分别为 `[0,59)`、`[59,88)`、`[88,143)`，键为 `WalkStart`、`Walking`、`WalkEnd`；只有中间片段循环。转换器用完整原视频计算共同构图，再从原视频直接编码各段，避免先有损压缩全片再压缩片段。

新走路视频需要首次确认起步/循环/收步边界，以及干净参考姿势。脚本不猜动作语义，也不自动修复循环接缝。基础包的 `WalkingSequence`、`Transitions` 和各段 `Alignment` 会保留；换了人物或构图后应重新检查这些人工校准值，必要时通过条目的 `alignment` 明确调整。

## 复用、缓存与安装

基础包为 `assets/dragon-girl-calibration-base`，输出包为 `assets/imported/dragon-girl-calibrated`，基准保留七段动作；当前输出再加入生气、睡觉三段、打瞌睡和屈膝礼，并用东张西望替换旧张望，共十三段视频；基准中的两段额外颜色参考视频用于锚点比较，不加入播放动作。睡觉用 `LyingDown`、`Sleeping`、`Waking` 分段键，三段共用完整源视频的站姿与校准，仅中段循环，程序将菜单合并为「待机 → 睡觉」，详见 [睡觉动作](睡觉动作.md)。原始 MOV、旧 0.40 基础包和校准前备份保留。配置的 `reviewed` 记录视频 SHA-256、源 SHA-256 和转换配方指纹；条件匹配时直接复制原 WebM，画面字节不变。东张西望源为 `animation/东张西望.mov`，复用 `IdleLook` 动作键替换旧张望。东张西望的鞋底标注和横向比例绑定标准化视频哈希；其发型轮廓与基准不同，按已测量的双脚间距保留原横向比例，头部中心和双脚中点仍作固定校准。屈膝礼使用 `animation/屈膝礼2.mov`，自动测量头部、双脚和横向比例，完整保留 143 帧。旧张望审核视频及原屈膝礼 MOV 保留。未校准动作仍支持源更新后的普通增量转换；已确认的两个互动成品采用严格审核，源变化时要求重新核对参考姿态与锚点。

缓存位于 `output/.cache/animation-import`，键包含源文件内容、编码/标定参数、处理模式、转换脚本和 FFmpeg 指纹。新素材还包含待机视频内容、参考标注、颜色策略与人工覆盖参数；标准化整段缓存独立存于 `output/.cache/animation-normalized`。参考或校准参数变化会重新校准，未变 MOV 的基础转换仍可复用。完整对比和测量图也缓存并核对哈希。成品复用与候选校准使用不同缓存键，避免相同配方误取已经变形的结果。名称或菜单分组变化只更新清单；源和编码配方未变则跳过编码和全帧解码。每次命中仍核对视频与预览哈希，缓存损坏会重新生成。修改转换器/FFmpeg 后会重新验证审核素材并重建缓存，但审核成品不重复编码。

新输出检查每帧的透明与可见内容、画布边缘、真实时间戳、尺寸、帧数、单片 256 MiB 解码上限，以及整库 1024 MiB 磁盘解码上限（0.51 起，转换脚本与播放器一致）。播放器仍按需缓存图片，常驻内存预算为 80 MiB。新增转换还检查站立高度和脚底舍入误差。验证完成后先放置带内容哈希的 WebM，最后原子替换 `skin.json`；若清单改变，上一份保存在 `skin.previous.json`。失败时不会替换已安装清单。

报告位于 `output/animation-import/last-run.json`；`preview.html` 展示各段首/中/末帧，PNG 保留透明背景。完整参数在各动作的 `*.conversion.json`，新转换失败信息在 `*.log`。机器检查通过后，仍应通过桌宠右键预览新动作，确认参考姿势、循环接缝和衔接效果。

双击入口只有在整个素材包验证成功后才切换 `local-data/settings.json` 的 `SkinDirectory`。安装记录保存在 `local-data/action-import-install.json`，按清单内容哈希判断是否需要重新加载；先生成再安装也能识别变化。如果内容与上次安装一致且已使用该包，无需重启。恢复内置素材可在桌宠设置中选择 `assets/dragon-girl-0.40`；恢复上一清单应在正常退出桌宠后，用 `skin.previous.json` 覆盖 `skin.json` 再启动。旧哈希视频不会自动删除，保证旧清单仍可恢复。

## Skill 与 Token

`pet-action-import` Skill 只负责维护登记、执行入口、读简短报告和处理例外；确定性转换逻辑全部在脚本内。直接双击或终端运行不需要模型，不消耗模型 Token。让 Codex 执行仍有少量对话与工具调用 Token，但无需每次重新读整套代码、设计转换流程或逐帧判断。

Skill 的项目维护源为 `skills/pet-action-import/SKILL.md`，安装副本放在当前用户的 Codex `skills` 目录。修改脚本正常使用项目文件；修改 Skill 后需要同步安装副本，新会话会重新发现它。

## 自动检查

```powershell
python tests/test_pet_video_converter.py
python tests/test_pet_action_import.py
python tests/test_pet_color.py
python tests/test_pet_anchor.py
python tests/test_pet_calibration.py
```

新增校准检查覆盖真实透明 MOV 全流程、颜色误差改善、固定纵向与跳跃位移、鲜艳特效保留、分段共同锚点、参考失效、缓存复用、缺失脚部及错误人工标注哈希时的清单保留。批量检查覆盖审核素材原字节复用、共享走路构图、分段帧数、菜单参数、缓存命中和失效、损坏缓存恢复，以及未登记/不透明素材/重复动作/非法目标目录时的清单保留。

后续可增加图形登记界面、参考帧选择器、循环接缝比较、旧缓存按引用清理，以及不同互动动作的行为分配。这些能力可继续扩展脚本和配置，不必增加 Skill 的长篇说明。
